# Security and manual recovery checkpoint — 7 October 2026

This is a focused engineering review and regression run, not an independent penetration test or a guarantee against compromise.

Production dependency audit found GHSA-hq66-cqwq-w95j in pdfjs-dist 5.7.284. The dependency is pinned to patched 6.2.108. PDF document cleanup now uses its loading-task API. The post-update production advisory scan reports zero advisories at the time of this check. CI now rejects high/critical production advisories. Dependabot configuration is prepared for weekly npm/GitHub Actions updates; its scheduled operation requires the configuration on the repository's default branch and appropriate GitHub settings, so do not assume activation from this feature branch alone.

Existing controls inspected: salted scrypt password hashes, opaque random sessions stored as digests in PostgreSQL, production Secure/HttpOnly/SameSite host-prefixed cookies, persistent account/IP login limits, same-origin and CSRF mutation protection, role checks for management decisions, parameterized database access, validated upload types/signatures/size limits, security headers/CSP, immutable historical snapshots and audit events. The Render database currently blocks external network access. No network restrictions were weakened, credentials exposed, shared passwords created or public backup endpoints introduced. An encrypted backup download requires Admin role plus current-password confirmation; restoration is an operator-only command into an empty database.

Remaining owner work: upgrade the existing expiring free database in place; verify managed recovery availability after upgrade; choose an always-on web service for daily operations; enable strong unique passwords and two-factor authentication on Render, GitHub and the email-provider account; store backup passphrase separately from the backup disk. Application-level MFA and a professional penetration test have not been implemented/performed by this checkpoint.

Manual daily encrypted downloads and a tested application-archive restore are implemented; no automatic daily job is deployed. The owner chose external-hard-disk storage instead of a new cloud backup account. A lost passphrase cannot be recovered. Managed PITR is still pending paid database activation. Test records and production data were not deleted. chint@powerzone.com.pk is the intended email sender; delivery and site-thread notification routing are a subsequent milestone, not live yet.
