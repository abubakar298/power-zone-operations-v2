# Survey intake, New BOQ and costing

New BOQ creates a new site. Site codes are suggested from a standalone 4–6 digit sequence, otherwise the first six alphanumeric characters, and stay editable text preserving leading zeros. Existing customer/site codes cannot be reused to avoid ambiguous BOQ numbers. The initial sequence is 001 for the newly created site; the R0 number is allocated only on final Save.

Survey drafts persist in PostgreSQL. Sources support PNG, JPEG, PDF and text, up to 8 MB each, ten documents per survey. PDF extraction supports up to five pages. Browser OCR uses bundled Tesseract English language data and PDF.js; source documents are never sent to an external OCR service. Clearly labelled unambiguous numeric fields can be applied as suggestions, but source review is required before saving an attached survey. Unrecognised fields remain manual entry. This is reviewed OCR intake, not unrestricted interpretation of arbitrary document layouts.

Source bytes persist in PostgreSQL rather than Render's ephemeral filesystem. Downloads require authentication, use attachment/octet-stream and never render uploaded active content inline. Upload rate and size limits apply. Existing account roles remain Admin / Management / Employee; master edits stay Admin only. Authenticated staff can create their own drafts and see saved BOQs; no unapproved detailed permissions matrix was invented.

The pure costing engine uses decimal arithmetic, current rate/rule versions, category-matched brands, numeric Needs Rate values with visible warnings, and approved specifications only. It implements the six locked inverter configurations and quantity rules. Preview fingerprints are canonical across PostgreSQL JSON storage; stale master changes require a fresh preview. Saving creates site, identity, R0 snapshot, attachments and audit entry in one transaction. A unique draft key makes repeated/concurrent Save idempotent. Database triggers reject edits/deletion of saved snapshots and attached source records.

Saved R0 records retain survey inputs, customer identity, selected brands and alternatives, configuration, rules, specifications/rate versions, detailed lines and costing summaries. The frontend shows the required seven detailed columns, no backend Category, financial/quantity separators, right-aligned numeric columns, category summary and EPC breakup. Printing/PDF uses the browser's print flow. Revisions, commercial pricing, quotations and inventory remain future milestones.

EPC reconciles to Labour 193,500; Earthing 90,000; Delivery 116,100; Installation 840,170. Tests cover string boundaries, all inverter configurations, battery limits, brand/category checks, decimal cable splits, immutable/idempotent saves, stale previews and authenticated reviewed sources.
