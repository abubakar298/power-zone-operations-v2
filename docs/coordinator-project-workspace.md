# Milestone 4 — Unified Project Workspace & Document History

Projects groups existing authorized records by customer ID and site code (case-insensitive). Unsaved site identities use customer/site name until a site code is recorded; no site/customer/document data is rewritten. Overview, Documents, Activity and Site Details use the existing six-basket overview and role-scoped saved records. Multiple active BOQs at one site retain their individual next actions rather than inventing one combined workflow status.

The new read-only /coordinator/projects and /coordinator/project APIs select explicit metadata, not snapshots, confidential prices, margins, C&I internal_cost_snapshot, management instructions or audit payloads. Every resource query applies existing ownership predicates; department boundary/authentication remain authoritative. Unknown or unrelated project keys return 404. Invalid/missing keys return 400. Management can inspect permitted team records; Atif only receives owned/assigned records.

BOQ revisions, quotation versions, all C&I saved versions, IPO submissions, issued IPO/PT, Operations handoffs and linked survey/approval/PO attachments retain original IDs and authorized export endpoints. Historical C&I Preview uses the exact version; Open current workflow identifies its separate latest-workflow behavior. Documents has View project; workflow pages resolve their project and provide a direct return. Existing deep links remain unchanged.

Chronological events include saved versions, submissions, approvals, revisions with shared reasons, Design assignment, customer confirmation, external approval and Accounts/Operations handoffs, each with recorded actor/date/version. The timeline cannot recreate unsaved changes or historical draft snapshots that were never stored. Current draft version uses its latest saved timestamp. No duplicate storage, new workflow states, migrations or business writes.

Verification: client/server typechecks and production build PASS; isolated native PostgreSQL project test PASS (all saved sources, chronology, counts/ownership, financial metadata absent, auth/department boundary, invalid/unrelated keys); C&I workflow test PASS with exact two-version project history and hidden-cost assertions. Disposable browser project check PASS: overview/site/activity/document sections, exact old C&I PDF, attachment link, current workflow, View project return, mobile containment and GET-only. Existing sidebar/navigation check PASS. Full integrated Coordinator checks will run at Milestone 7.

Limits: historic drafts only have their latest saved version; linked files remain subject to their existing download authorization. Records missing a site code are explicitly grouped by name; no invented identity or master edit. This read-only prelaunch index is unpaginated; future scale may warrant pagination, without omitting existing project history now.
